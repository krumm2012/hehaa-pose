# Tennis Analyzer 最近修改汇总（2026-10-05）

本汇总覆盖 2026-10-04 至 2026-10-05 的指标审计、实时观测、源时间、人工复核与报告迭代。代码与验收记录截止提交 `05ae232`，最新工程提交为 `b33956f`，分支为 `algo-2.0`。本次整理只更新文档。

Tennis Analyzer 继续承担轻量实时感知、独立原始双视角记录、挥拍与触球候选、证据回放及展示；Tennis-Vision 用于离线审计。双视角一致性、模型辅助复核和回归通过均不能代替独立准确性验证。Vision 历史拟合不为迎合动力链结果重写。

## 1. 已修改的行为

### 1.1 原始观测与背面姿态

- 保留原模型分数、选择分数、观测来源、源帧身份及补点/缓存点标记；重新解析双视角数据时不把旧点或镜面补点变成新鲜观测。
- 背面人物选择加入镜面区域、躯干尺度和时序连续性检查；缺少可靠肩部映射时停止镜面补点。
- 骨架显示区分可信观测与旧点、补点，低分或遮挡关节不再强行画成完整实线手臂。
- 球与球拍的缓存、叠加图形恢复和未知来源不进入新鲜触球测量。触球仍是候选，不能因球拍接近就升级为已确认触球。
- 新鲜测量拒绝 NaN、Infinity、布尔值、数值字符串、超范围模型分数及退化球拍框；非法关节不再生成假的 0° 或 180°。实际选样的拒绝原因进入指标证据。

相关实现：`observation_policy.py`、`ball_observation_contract.py`、`dual_pose_estimator.py`、`dual_view_renderer.py`、`swing_biomechanics.py`。

### 1.2 源时间与候选窗口

- reader/FrameRecord 区分文件媒体 PTS、接收时间、估计或不可用时钟，并保留源帧身份。测量时间不从处理速度、墙钟或声明 FPS 推导。
- 运动候选、平滑、球质量窗口及实时等待/去重采用合格源时间；旧 25Hz 参数只保留为历史候选调参单位。
- 身体与轨迹统计改用媒体时间：触球及端点窗口为 ±0.08 秒，准备屈膝按起始至触球的前半时间，肩线基线取前四分之一并限制为 0.16 秒，回位参考选择触球后 0.40 秒附近的实际事件内观测。
- 分类使用触球前 0.56 秒至后 0.08 秒，触球几何使用前后 0.12 秒，并与实际分段范围取交集；分类不足 3 个样本返回 `Unknown`，不扩成整个事件来补证据。
- 缺失或重复锚点不借邻帧；无合格时钟的兼容候选明确标为未核验，不能据此生成可信测量秒数。
- 事件媒体经过时间与模型阶段覆盖分别记录；模型回位候选的 0.08 秒低运动支持、至少 3 个连续观测仍是启发式候选规则。

操作定义见 [源媒体时间 ADR](adr/0003-source-media-time-contract.md)、[运动源时间](MOTION_SOURCE_TIME.md) 和 [事件源时间](EVENT_SOURCE_TIMING.md)。

### 1.3 动力链与确定性公式错误

- 修复肩线角度跨 ±180° 的基线错误，例如 179° 与 −179° 的变化约为 2°，不再误算为 179°。
- 关键点缺失、源身份冲突或时间断点切段；每段独立微分、滤波和找峰，不跨遮挡拼接出假峰。
- 无法定位时间的帧计入保守覆盖分母，避免少数合格帧被报告成 100% 覆盖。
- 髋—肩与肩—拍均传播两端峰宽和采样间隔；延迟区间含零时保留“先后未分辨”，不把 Δt=0ms 当成动作不连贯。
- 双视角各自保存峰值与资格，冲突不平均成一致；多峰、宽峰、边界峰和不足样本明确拒绝。
- 旧信号峰值只保留审计候选，不再按 FPS 生成毫秒值或输出 `OPTIMAL` / `DISCONNECTED` 技术结论。

当前测量是二维像面运动学峰值时序，不能证明真实轴向转动、力、力矩或能量传递。详见 [动力链交叉验证](KINEMATIC_SEQUENCE_CROSS_VALIDATION.md)。

### 1.4 球拍速度与其他代理指标

- 球拍速度改为合格连续检测框中心的像素位移 / 源时间，单位为 px/s；未标定时不输出虚假的 km/h，也不把检测框中心叫作真实拍头。
- 球拍像面轨迹方向和最低点到触球候选的上升比分别判定资格；端点重合时方向角为空，合格上升比 0 保留。
- 足部连线像面倾角、髋部像面上移、躯干中心像面位移、肩宽角度代理、正背肩宽比和镜面手腕偏移均限制物理解释。
- 足部跨度及髋上移阈值按事件身体宽度归一化，分别为 0.2 和 0.04；仍未完成定位误差标定，不能把小位移解释为蹬地不足。
- 统一每项指标的公式、坐标系、时间窗口、有效条件、单位、来源帧和缺失原因；当前定义为 `tennis.metric-contract.v4`。

当前公式以 [指标计算契约](METRIC_CALCULATION_CONTRACT.md) 及 `metric_contracts.py` 为准。[算法 2.0 设计记录](ALGO_2.0_DESIGN_AND_PROGRESS.md) 中早期“全域转肩”“肩胛收缩”等表述属于历史设计，不能作为准确性标准。

### 1.5 JSON、OSD、报告与技术评分

- 指标数值、单位、来源、窗口、资格及缺失原因贯穿事件 JSON、控制页、OSD 和报告；统计行数与去重指标种类分开显示。
- 区分当前帧、触球窗口和事件窗口；指标缺失、观测资格与评分禁用是不同原因，缺失不默认计 0 分。
- 证据百分比明确标为启发式、未校准参考；复核提示不显示成技术评分。
- 五个评分维度提供阻断原因，但阻断清单本身不是评分规则。代码内已批准自动技术规则集合保持为空，高分、历史子分、外部资格或人工评分不能单独开放自动建议。

所有 OSD/统计口径的现场对照仍待完成。评分政策见 [练习评分](PRACTICE_SCORING.md) 及 [事件源时间与建议资格](EVENT_SOURCE_TIMING.md)。

### 1.6 人工辅助标注、独立标注与仲裁

- 自动预标注、逐点修改、不可辨认、全部复核、草稿恢复、导入续标、快捷键和漏标定位均保留；记录原建议、修改及批量/逐点确认方式。
- 模型辅助复核保持独立来源标签，不能通过改文件名或批量确认变成独立真值。
- 连续 22 帧、双视角、左右肩与左右髋的无模型提示计划共 176 项；最新计划显式保存关节范围。
- 新增两位独立标注者的原稿对照与仲裁工具，差异需明确裁决，不按容差自动平均；原稿、计划、裁决哈希绑定，生成结果不覆盖原件。
- 人工指定开始/触球/结束源帧保持原值，缺失或重复观测单独报告；采集器沿用事件触球锚点，不按更高模型分数重新选择。

独立计划目前仍为 **0/176、未确认**；此前用户提交的模型辅助复核已保留，但不能用于独立误差或置信度校准。工具及操作见 [独立关节点验证](INDEPENDENT_JOINT_VALIDATION.md)。

### 1.7 评估、报告与编辑器身份校验

- Python、CLI、后台、实时报告与独立报告校验完整输入后再匹配/发布；源帧和事件 ID 要求非负安全整数，不取整或强制转换，合法 0 保留，显式 null 不借旧字段。
- 重复事件/标注身份、错误来源链接、反序区间、非法容差及非布尔复核状态拒绝。CLI 输出不能覆盖原事件/参考文件，包括符号链接和硬链接。
- 两种编辑器在导入/恢复前校验整个计划，包括与已有卡片的 ID 冲突；重复导入不堆积人工事件，恢复保留标注身份。
- 模型缺少触球时不从 Coach 补回；缺触球/峰值的时间轴不生成 0 帧标记，空定位不跳到 0，真实零帧仍可使用。
- 参考评估保留实际计数、差值、IoU、事件 Precision/Recall/F1；类型和触球的匹配比例使用独立命名。旧 `accuracy` 兼容字段为空，未复核页面不显示比例，完成辅助复核只显示参考一致性。

当前政策：`evaluation_identity_v1_strict_source_frames`、`report_identity_v1_strict_event_and_coach_ids`、`manual_annotation_identity_v2_event_links`。**声明 ID 校验未完成跨会话源内容绑定**，详见 [参考评估契约](EVALUATION_REFERENCE_CONTRACT.md)。

### 1.8 同源证据回放与 Tennis-Vision 离线对照

- 冻结证据包保存视频、帧记录、模型、配置与代码身份，支持确定性重放；重新运行像素检测另行核验输入视频 SHA，缺失或不符时在推理前拒绝。
- Analyzer/Vision 的离线关联核验实际视频字节、源帧身份及 Viewer 元数据；相同文件名或近似 FPS 不建立对应关系。
- 50.03 原片 250 帧与 Vision 标准化副本 249 帧、SHA 不同，12 个事件锚点仍待逐帧映射。另生成同一 Vision 输入的 Analyzer 验证会话，不改原片结果或历史拟合。
- 对照页提供各自入口及帧号供人工定位；三维播放器自动同步、原始曝光对应关系和独立三维准确性尚未验收。

详见 [跨项目证据关联](CROSS_PROJECT_EVIDENCE.md) 和 [动力链验证路线](KINETIC_CHAIN_VALIDATION_ROADMAP.md)。
