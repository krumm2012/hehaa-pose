# 运动候选的源时间契约

2026-10-05。策略 `motion_candidates_v1_source_time`，实现于
`motion_time_contract.py`、`swing_motion_features.py`、`swing_event_segmenter.py`
和 `RealtimeSwingEventEngine`。这是候选计算的工程修正，独立准确性尚未验证。

## 时钟与资格

完整 `tennis.source-time.v1` 要求源帧身份与当前记录一致、非负有限时间、
来源为文件；`media_pts/reported` 与 `nominal_fps/estimated` 分别标记。
未知格式、错误身份、无效时间不从兼容 `timestamp` 或接收时间补出测量秒数。
连续原始拍框的像面速度拒绝估计时钟、补点和源帧缺口。

分段仅在整个上下文的源PTS严格递增且来源一致时使用合格媒体时间。
旧格式单调 `timestamp` 标为 `legacy_timestamp_unverified`。显式源契约无效、
混用来源或重复/倒退时，候选继续采用 `processing_order_unverified` 顺序启发式，
原始记录保持不变，源媒体时间统计仍不通过。源PTS不证明实际曝光。

## 信号、公式和窗口

| 输出或步骤 | 定义与单位 | 资格与缺失 |
| --- | --- | --- |
| 原 `wrist_speed/racket_speed/ball_speed` | 相邻观测像面位移，px/observation | 保留兼容字段；不是px/s或km/h；缺点沿用原候选零值语义 |
| `candidate_motion` | 位移 / (25 × 源dt)，px/25Hz参考区间；加速项是候选率差 | 新鲜连续源身份及正同基准dt；补点明确标为interpolated；无合格dt是顺序启发式 |
| 25Hz参考 | 历史候选阈值的固定调参单位 | 不代表输入FPS、曝光采样率或可获得的时间精度 |
| `racket_speed_px_s` | 原始拍框中心位移 / 已知dt | 仅连续原始框；估计时钟、无效来源、缺点和插值拒绝；历史时间标为未核验 |
| 球拍短缺口补点 | α=(t_missing−t_left)/(t_right−t_left)，线性插值 | 合格源PTS、连续源ID、严格递增且端点间≤0.12s，缺点≤2；仅用于候选，不是观测或速度测量 |
| 中位平滑 | 当前及过去0.08s的候选信号上中位数 | 合格PTS按时间取窗口；无合格时钟维持3观测启发式 |
| 动作段内部间隙／合并 | `max_internal_gap/25`、`min_event_gap/25` | 合格PTS比较经过时间；无合格时钟比较顺序；最少帧数仍是观测数量要求 |
| 球的触球质量窗口 | 候选触球PTS±0.16s（历史4/25参考） | 保存实际帧ID、时间依据；覆盖率是保留记录中球检出比例，不是时间覆盖率 |
| 肩／髋旧角度步长 | abs(wrap180(angle_i−angle_previous)) | deg/observation，修正179→−179的358°假跳变；不是轴向旋转角速度 |

0.12s、0.08s、像素跳变门槛及其他调参量仍是启发式，未经独立误差标定。
补点、顺序启发式和原始位移不能升级为技术评分证据。

## 实时缓存、等待与去重

- 默认最多200条FrameRecord；合格源PTS上下文另外限制为最多8秒。
  数量上限是存储容量，高采样率或丢帧下可能不能提供完整8秒，快照记录容量状态。
- 默认等待0.6媒体秒、峰值去重至少1.6媒体秒；不应期按固定25Hz参考解释。
  原帧参数保留兼容入口，CLI帮助和配置注释明确新含义。
- 合格候选使用源PTS判断等待、峰距和不应期。无合格时钟维持明确标记的帧身份启发式。
- 视频结束时可保存未完成等待的候选，`completion_status` 标为
  `source_end_unsettled_candidate`；报告提示人工检查动作完整性，不宣称确认完整挥拍。
- 人工改边界重新计算候选摘要、质量窗口和媒体时间，清除旧运行等待状态。
- 证据包保存窗口及策略，重放使用同一契约。新分析记录相关模块导入时源码哈希。
