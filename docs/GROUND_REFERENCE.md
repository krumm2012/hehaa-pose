# 地面四点标定与双视角投影参考

2026-10-05。版本 `tennis.ground-calibration.v1`，策略
`ground_reference_v1_original_pixels_ankle_candidates`。

Tennis Analyzer 使用独立的二维平面映射核对脚踝观测。不新增模型推理、三维重建或技术评分。
Tennis-Vision 的旧四角可导入为参考；旧相机焦距、三维 basis、已有 H 不参与新映射。
历史原片、观测、报告和 Vision 拟合不回写。

## 操作

### 导入为机位共享标定（2026-10-05 升级）

页面新增“导入为球道 / 机位标定”：选择 **Court 02 Main Camera**，选择
Analyzer 导出的 JSON，再点击“应用 JSON 为机位标定”。不需要为注册共享版本
连接 RTSP 抓图。完整文件先校验，非法 JSON、几何或目标机位不匹配不改变已有版本。

用户提供的 `analyzer_ground_calibration (2).json` 已注册为球道 2：3.3×4.8 米、
2560×1440、正面几何已确认；镜中实体对应仍为 false。此标记不会因导入而升级。

注册后的机位共享版本**优先于旧的单视频版本**。球道 2 实时输入自动加载；
本地视频必须明确选择“绑定球道 2”。其他机位、未绑定视频不继承。
实际原图尺寸不同则预览提示重新核对，分析拒绝地面测量；不自动缩放或借旧单视频版本。
相机地址/query 改变会失去原共享绑定；机位、变焦或裁剪改变也需要人工重标定，
相同分辨率不能证明几何未改变。

加载共享版本后“保存范围”默认切换为“绑定机位共享标定”，编辑后保存更新共享版本。
选择“仅当前输入”会保留单输入记录；已注册的共享机位仍以共享版本为准。
导出 JSON、源视频、既有单视频修订及 ROI 配置保持独立。

共享版本位于 `data/control_ground_profiles/`，保存原始校验后标定与相机身份，
不可变修订、原子 current 索引。运行时为明确绑定输入生成独立内存副本；实际视频 SHA
和原标定的源绑定分别记录，不能把机位共享声明说成视频字节相同。
session、FrameRecord 和事件的 `application` 保存 profile ID、原标定 ID、
相机绑定与当前输入绑定。事件混合共享版本不汇总差值。
策略为 `ground_camera_profile_v1_explicit_mapping_exact_size`，追加源码身份，
不改变旧 `tennis.ground-calibration.v1` 修订的归一化和 ID。

### 当前输入独立标定与草稿

控制台的“地面四点标定 / 双视角参考”打开 `/ground-calibration`。

1. 选择机位或上传视频；本地视频可绑定机位。加载冻结的当前原图。
2. 手动选四角，或载入球道 2 / 导入 JSON。球道 2 参考来自 `30.56`，原参考尺寸为
   1280×720；用户已确认实体矩形 AB 宽 **3.3 米**、AD 长 **4.8 米**。
3. A 为原点，B 沿宽方向，C 为对角，D 沿长方向。镜中 A′–D′ 对应相同实体角点，
   不能因镜像而按画面左右重新排序。点击、拖动、方向键 1 像素或 Shift+方向键 10 像素微调；支持撤销。
4. 不同原图尺寸默认拒绝导入。仅当同一画面等比例缩放时可勾选换算；裁剪、变焦、
   镜面或机位移动须重选。等比例并不证明画面几何相同，导入仍撤销当前几何和实体对应确认。
5. 核对当前四角与机位、镜中实体对应，分别勾选确认。可添加非拟合四角的独立实测地面检查点。
6. 保存或导出。可保存未确认草稿，但它不能授权测量。保存版本供**下一次分析**加载，
   不修改已运行会话、ROI 或镜面配置。

球道 2 尺寸已确认，当前画面的角点核对是单独资格。实测宽长不自动批准旧四角或真实足部位置。

## 坐标与公式

源坐标为未裁剪、未缩放、未翻转的原图像素，x 向右、y 向下。
FrameRecord 声明 `pose_observation_coordinate_space=original_source_pixels`。
正背原始姿态分别通过既有 ROI 逆变换还原，不使用融合点补齐任一视角。

实体平面定义为 A=(0,0)、B=(w,0)、C=(w,l)、D=(0,l)，单位米。
正面和镜中各自使用四对点，归一化后解 8 自由度单应矩阵 H。
保存、读取时重新计算 H；重复、交叉、共线、越界、病态及奇点映射拒绝。

对像素 p=(x,y)，候选投影 q=H·(x,y,1) 后除齐次分母。
同一源帧、同一解剖脚踝的双视角差值为
`delta = norm(q_front - q_back)`；不平均成融合足点。
图中网格将实体平面等分十份再逆映射，供几何核对，不是实测精度证明。
网格在加载标定时缓存，显示时只使用该帧裁剪映射，包括背面水平翻转。

额外检查点记录 `error_m=norm(H(image_point)-measured_world_point)`。
拟合四角和重复检查点拒绝；残差仅为用户声明参照的误差，不自动批准准确率。

## 观测资格与缺失

| 检查 | 要求 / 拒绝原因 |
| --- | --- |
| 输入绑定 | 视频实际字节 SHA256 或去 userinfo 的相机地址摘要，再加机位 ID；不匹配拒绝 |
| 图像几何 | 原图尺寸必须相同，当前画面几何已确认；不能按 ROI 尺寸或旧标定猜测 |
| 坐标 | 显式原图坐标契约；缺失契约为 `observation_coordinate_space_unverified` |
| 脚踝观测 | 独立视角原始模型观测、`observed=true`、非镜面补点；分数有限且在 [0,1]、至少 0.5 |
| 时间身份 | 源帧 ID 明确整数、与当前帧完全一致；合法 0 保留，旧帧、布尔、小数等拒绝 |
| 地面区域 | 点位在原图和标定四边形内；域外不外推 |
| 配对 | 两端均合格，镜中实体对应已确认；否则差值为 null |
| 事件汇总 | 只使用事件源帧区间，保存实际源帧列表；混合标定版本或重复源帧不汇总差值 |

0.5 是已有观测过滤门槛，不是位置准确概率。抬脚或腾空时脚踝位于地面之上，
将它投影到地面会产生视角相关偏差；即使差值小也不能证明着地或定位正确。

## 数据与消费者

FrameRecord 的 `ground_reference` 保存标定 ID、来源绑定、源帧、资格和各视角
`image_xy`、原模型分数、`projected_xy_m` 及拒绝原因。
`position_m=null`、`ground_contact_verified=false`、`accuracy_validated=false`、
`coaching_eligible=false` 始终保留。当前模型只有 COCO 脚踝，没有脚底或接地标签。

事件 `ground_reference.feet` 按脚踝保存合格配对数和投影差的样本中位数，
不是时间加权中位数或统计置信区间。缺值不补零。
控制页、实时报告、独立报告和 OSD 显示该参考；OSD 是当前帧，报告是事件区间，
两种窗口不同。它不是新增可评分技术指标，也不计入原有技术评分规则。

单输入版本放在 `data/control_ground_calibrations/`：不可变 `<calibration_id>.json` 与
按输入绑定的原子更新 current 索引。未注册共享机位时，输入改变不继承旧视频标定；相机用户密码轮换
不改变地址身份，相机 query（例如 channel）变化改变绑定。摘要不发布原地址、查询或凭据。
相机物理移动无法由地址自动识别，仍需操作员重新核对。

预览/保存 API 使用既有本机控制 token；保存还要求匹配最近冻结预览的来源和原图尺寸。
无效保存保留旧修订。标定加入 `analysis_build` 的策略及源码身份。
