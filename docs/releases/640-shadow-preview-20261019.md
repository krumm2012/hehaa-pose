# 640 shadow preview · 2026-10-19

此预发布让已有Tennis Analyzer环境可在控制台选择640七点球拍shadow模型，查看逐帧观测，
同时保留旧版球拍选择、球选择、挥拍事件及Coach。默认仍为旧版。
这是受控本地内测版本，尚未通过正式稳定25FPS和active/exclusive检测质量验收。

## 安装与启动

适用于已安装原球检测模型、双人体模型及项目Python环境的macOS设备。
Release仅另附640七点球拍模型，不包含全部基础模型或虚拟环境。
本轮环境为Python3.9.6、macOS26.7.1、coremltools9.0、OpenCV4.13.0.90、
numpy2.0.2、Pillow11.3.0；其他环境需要独立验证。

先检出版本，然后下载同一版本的所有附件，在附件目录校验SHA256SUMS，再解压模型至项目根目录：

```bash
git checkout 640-shadow-preview-20261019
mkdir -p /tmp/tennis-640-shadow-preview-20261019
gh release download 640-shadow-preview-20261019 --repo krumm2012/hehaa-pose \
  --dir /tmp/tennis-640-shadow-preview-20261019
```

在下载目录执行 `shasum -a 256 -c SHA256SUMS`，然后回到项目根目录。
若已有同路径候选，先运行模型校验工具；不匹配时保存旧候选后再解压，避免覆盖已有实验。
新安装按以下步骤解压和启动：

```bash
tar -xzf /tmp/tennis-640-shadow-preview-20261019/racket-pose-640-shadow-preview-20261019.tar.gz -C .
venv_yolo26/bin/python scripts/verify_shadow_release.py
venv_yolo26/bin/python local_control_panel.py --port 8766
```

控制台打开 `http://127.0.0.1:8766/`。选择本地视频，绑定实际球场机位，并检查ROI及镜面配置。
本版本保留当前标定文件；部署到其他机位需重新校准。

- 启动球拍模型：`640 ALL：性能预览（影子）`。
- 球拍方案：界面自动固定为影子对照，事件和Coach沿用旧链路。
- 处理方式：连续处理；启动调度：同帧并行；球拍图像传输：共享源帧。
- 启动后核对日志中的 `640x640 | ALL | shadow` 与旁路汇总的模型哈希。

模型路径为 `models/racket_pose/candidates/bn-repaired-640-v1/racket_pose_bounded_fp16_640.mlpackage`，
按项目 `model_digest` 算法计算的SHA256为：

```text
0dec1259f50b2cfb286f3ed5408a2f5f589749a0ddaf7a9b8a4139f29c1a025e
```

文件附件校验和与模型目录身份哈希采用不同的输入，分别由SHA256SUMS和模型校验工具检查。
包内为RGB640×640输入、`[1,26,8400]`输出，七点拓扑与原图坐标还原沿用集成接口。
原始存在非有限输出的640包未作为此Release模型。

## 本版改动

- 支持640/960显式输入合同，校验包尺寸、候选数和验收尺寸；640不能借用960质量收据。
- 控制台增加模型选择及最近启动身份，640仅开放shadow；旧版不启动七点进程。
- 保留逐帧处理、共享源帧租约/代次校验及现有双人体、球、事件、Coach与证据重放。
- 修复ROI管理器初始化覆盖及ROI编辑预览被双视图画面覆盖的问题，保留当前人工标定。
- 字体缓存、文字批量/局部转色、先缩放再转换检测输入，以及复用逐帧JSONL编码刷新快照。
- 记录裁剪、视图、HUD、卡片等渲染阶段，保留名义输入积压、编码和显示提交的独立计时。

## 核验结果及适用范围

最终推理/渲染实现上，49.43同源旧版/640 shadow各250帧处理、显示、编码和重放完整。
逐帧业务观测、事件窗口和Coach内容一致。此轮shadow为25.18FPS，名义输入至输出P95约50.7ms。
这是单段单轮结果，不能替代此前慢轮，也不是摄像头曝光到屏幕显示延迟。

渲染三阶段、三段对照共2250帧完整，最终渲染P95为7.42/7.95/9.67ms，
新鲜基线为11.27/12.24/11.99ms；最大单帧为19.23/14.75/23.19ms。
固定画面的普通、教练文字和遥测卡片输出像素一致。
快照复用主要减少重复序列化及单轮最大尖峰，没有保证所有分位数改善。
历史三视频三轮的输出范围曾为23.46–25.33FPS，保留该限制，不授予稳定25FPS标签。

发行前152项Python相关回归、3项ROI前端测试及JS语法检查通过。

## 故障、回退与未完成验收

连续shadow为保持全部源帧，会等待新模型同源结果。模型加载失败、原生崩溃或单帧超时会使本轮
会话失败；不会把不完整结果标为完整成功。这不是新模型出错后旧链路无阻塞继续的线上影子方案。
共享源帧只在租约有效时读取，超时/退出后终止工作进程再释放租约。

停止当前会话，在控制台将启动球拍模型切回“当前已配置模型”，球拍方案选“旧版”，再启动即可回退；
旧版不加载七点模型。保留历史标注、证据和原模型。

正式放行仍需最终冻结构建的九段视频三轮、10分钟连续运行/内存队列检查、完整工作流与
网络/语音旁路故障验收。640镜面球拍质量仍需人工核查后才可考虑active/exclusive。
测试注入的崩溃和卡住场景不能替代所有真实设备故障。
本版没有更新增强模式质量收据，`docs/releases/640-shadow-preview-20261019.json` 仅定义发布身份。
