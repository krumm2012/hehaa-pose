# 功能需求与验收基线

更新：2026-09-16；对应 `new` / `0f43470`。

本文件是当前实现的可追溯需求快照与待办建议。仓库以 GitHub Issues 为正式需求/PRD 跟踪入口，参见 `docs/agents/issue-tracker.md`；下列编号为文档索引，不代表已创建 Issue，也不代表待办已获发布验收。

## 1. 用户与目标

- 训练操作者：选择机位、启动会话、查看实时建议和听取播报。
- 人工复核者：修正事件和漏检，评估并解释 Coach 差异。
- 算法维护者：用固定输入比较模型、阈值和分段规则。
- 运维人员：复现环境、定位错误、保存会话证据并回退版本。

| 编号 | 需求 | 实现入口 | 验收方式 |

## 3. 待完成质量要求

### 2026-09-20 第一批优化

- 新实时事件快照保存生效 Coach 配置；人工重算继承配置和惯用手，并记录来源。旧报告没有 Coach 配置时使用默认值，明确标记 `legacy_defaults`，不能视为精确复现原设置。
- 有效挥拍标注区间完全缺少帧证据时拒绝重算；有缺帧但区间非空仍沿用原质量门控。
- 标注校验和全部重算完成后才发布产物，避免计算异常留下部分更新；同一服务进程内的校准请求串行执行。
- 此批未实现跨进程锁或多文件磁盘事务；中途 I/O 失败和 finalized 后再次提交 provisional 的历史文件管理仍需后续完善。

### 2026-09-20 第 3/4/5 项实现进展

Q01–Q04 已实现语音通信超时/取消、独立播放器、报告健康检查、单待写快照合并，增加故障注入测试。DeepSeek 任务容量和 Future 生命周期已限制。Q05 固定 MLX-Audio commit，视频环境的全部依赖锁定仍待后续工作。

模块拆分为 `tts_worker_client.py`、`streaming_audio_player.py`、`latest_snapshot_queue.py`，保留原有事件结构与外部入口。没有对分段阈值或算法做整体验证迁移。真实模型已以缓存权重离线生成 WAV；真实扬声器连续性、RTSP 长会话以及网络故障仍需现场验收，不能以单元测试代替。

建议保留至少 15 FPS 的历史验收目标，事件分析间隔 5 个处理帧、结束等待显式设为 15 帧。该目标需实测，`output_fps=15` 不是吞吐验收。尚未确定跨机位准确率、首声时延和长会话资源硬阈值，应先采集基线再批准门槛。

## 4. 算法验收边界

- 检测：球与球拍分别统计 Precision/Recall；主球选择正确率单独评价。
- 事件：计数、匹配 Precision/Recall/F1、边界误差、类型准确率分别报告。
- 触球：区分有视觉证据的候选与峰值回退；报告误差分布和覆盖率。
- Coach：评价证据充分性、建议正确性及人工接受度；技术动作质量与视觉证据质量分开。
- 性能：源帧率、处理帧率、输出帧率分开；事件等待、网络建议、TTS 首声与完成延迟分开。
- exp005 仍为候选。历史兼容报告使用旧入口且含覆盖层输入，不可直接当作当前主入口性能或纯模型精度结论。

## 5. 非目标与验证记录

当前不承诺多路同时分析、自动训练、真实三维球速/旋转/拍面测量或云端多用户权限系统。

最近代码审查运行了 TTS、实时运行时、输出、控制面板、校准、进程监督及 Coach 的 62 项单元测试，全部通过。它们不包含真实 RTSP、MLX 声音连续性或模型精度验收；新增质量要求需要补充故障注入与真实输入验证。
