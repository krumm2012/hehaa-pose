# 功能需求与验收基线

更新：2026-10-20。当前正式Shadow版绑定`0b5f4e5`，范围见[640 Shadow stable](releases/640-shadow-stable-20261019.md)；历史质量提案及未完成准确率要求仍保留。

本文件是当前实现的可追溯需求快照与待办建议。仓库以 GitHub Issues 为正式需求/PRD 跟踪入口，参见 `docs/agents/issue-tracker.md`；下列编号为文档索引，不代表已创建 Issue，也不代表待办已获发布验收。

## 1. 用户与目标

- 训练操作者：选择机位、启动会话、查看实时建议和听取播报。
- 人工复核者：修正事件和漏检，评估并解释 Coach 差异。
- 算法维护者：用固定输入比较模型、阈值和分段规则。
- 运维人员：复现环境、定位错误、保存会话证据并回退版本。

## 3. 质量要求、历史实现与当前状态

### 2026-09-20 第一批优化

- 新实时事件快照保存生效 Coach 配置；人工重算继承配置和惯用手，并记录来源。旧报告没有 Coach 配置时使用默认值，明确标记 `legacy_defaults`，不能视为精确复现原设置。
- 有效挥拍标注区间完全缺少帧证据时拒绝重算；有缺帧但区间非空仍沿用原质量门控。
- 标注校验和全部重算完成后才发布产物，避免计算异常留下部分更新；同一服务进程内的校准请求串行执行。
- 此批未实现跨进程锁或多文件磁盘事务；中途 I/O 失败和 finalized 后再次提交 provisional 的历史文件管理仍需后续完善。

| 编号 / 优先级 | 改进项 | 目标（历史提案；实现进展见表后） |
| --- | --- | --- |
| Q01 / P1 | TTS 有界等待与退出 | 日志量超过管道容量不会死锁；模拟不响应 worker 在配置超时内失败；停止可回收 worker |
| Q02 / P1 | 独立播放消费 | 生成抖动测试中缓存持续消费；记录首声延迟、欠载数、完整播放状态 |
| Q03 / P1 | 报告错误即时可见 | 注入磁盘写错误后运行期可见失败；恢复策略有上限，无静默永久停更 |
| Q04 / P2 | 合并待写快照 | 慢磁盘下待写快照数量有界，最终快照最新且事件 JSONL 历史完整 |
| Q05 / P2 | 环境可复现 | 固定 MLX-Audio commit，记录解释器/模型版本；新环境能通过核心回归 |
| Q06 / P2 | 冻结干净视频验收集 | 按视频/球员/机位划分，避免相邻帧泄漏；报告分组指标和样本量 |
| Q07 / P2 | 长会话性能 | 固定硬件、分辨率、模型、ROI 及旁路组合，测吞吐、丢帧、内存、延迟分位数与停止耗时 |

### 2026-09-20 第 3/4/5 项实现进展

Q01–Q04 已实现语音通信超时/取消、独立播放器、报告健康检查、单待写快照合并，增加故障注入测试。DeepSeek 任务容量和 Future 生命周期已限制。Q05 固定 MLX-Audio commit，视频环境的全部依赖锁定仍待后续工作。

模块拆分为 `tts_worker_client.py`、`streaming_audio_player.py`、`latest_snapshot_queue.py`，保留原有事件结构与外部入口。没有对分段阈值或算法做整体验证迁移。真实模型已以缓存权重离线生成 WAV；真实扬声器连续性、RTSP 长会话以及网络故障仍需现场验收，不能以单元测试代替。

15FPS保留为历史目标，不是640正式版当前门槛。640 Shadow采用：九视频各三轮输出≥25FPS、名义输入到输出P95≤250ms、250/250源帧完整、无持续积压；连续长测预热后RSS增长≤10%，队列有界，保留报告/片段/显示/编码/重放。本地长测为一进程61次原片引用，共15,250帧；不等于真实摄像头或RTSP上游验收。

### 2026-10-19 正式640 Shadow结果（2026-10-20文档同步）

- 同一冻结构建27/27、长测、9/9业务对照及133项定向回归通过。
- 长测稳定25.069FPS、P95 88.6ms、RSS增长3.28%；Q07的这一特定本地配置通过，其他硬件/RTSP长会话仍待验收。
- 原两段网络/语音故障测试出现约21.9FPS慢轮，全部保留；按用户要求固定串行复验两段各三轮及一段对照，7/7通过，没有放宽门槛。
- 该结论不证明CPU争用是旧停顿的唯一根因，也不包含真实语音成功合成/扬声器并发的完整性能资格。
- 默认业务仍legacy，640仅显式Shadow；独立球拍质量、跨机位准确率、真实触球及三维测量没有因性能通过而自动获批。

## 4. 算法验收边界

- 检测：球与球拍分别统计 Precision/Recall；主球选择正确率单独评价。
- 事件：计数、匹配 Precision/Recall/F1、边界误差、类型准确率分别报告。
- 触球：区分有视觉证据的候选与峰值回退；报告误差分布和覆盖率。
- Coach：评价证据充分性、建议正确性及人工接受度；技术动作质量与视觉证据质量分开。
- 性能：源帧率、处理帧率、输出帧率分开；事件等待、网络建议、TTS 首声与完成延迟分开。
- exp005 仍为候选。历史兼容报告使用旧入口且含覆盖层输入，不可直接当作当前主入口性能或纯模型精度结论。

## 5. 非目标与验证记录

当前不承诺多路同时分析、自动训练、真实三维球速/旋转/拍面测量或云端多用户权限系统。

历史2026-09代码审查的62项TTS、运行时、输出、控制面板、校准、监督及Coach单元测试通过；正式640冻结构建另有133项定向回归，见版本说明。它们不包含真实 RTSP、MLX 声音连续性或模型精度验收；新增质量要求需要补充故障注入与真实输入验证。
